# Minimal live rollout design — proposal only

Keep `model_runtime.py` intact as the historical implementation and fallback. Add one small `selected_model_runtime.py` with a fixed registry of the historical provider and the authenticated vanilla candidate. Both model routes and availability metadata must consult that same selector. No kernel, native search algorithm, experimental authority, remote endpoint or new framework is needed.

Use a small local selection record containing only an allowed provider ID, not client-supplied paths or model options. The candidate's `LocalCandidateSpec`, source hashes and genuine GPU/local gate receipts live in the fixed registry. Read selection through the existing bounded/no-symlink metadata helper, retain its hash for the request, and check it at finalization. Missing selection may explicitly default to historical; a malformed or failed candidate selection must report unavailable/error, not silently run the old model. Rollback selects historical for a fresh worker. The server strips arbitrary environment variables at `server.py:179`, so an unpropagated environment toggle would not reliably select both routes.

## Required compatibility facade

The proposed `CandidatePolicy` already supplies `propose`, actual `calls`, `forward_attempts`, `forward_passes`, `generated_tokens`, `attempts`, `evaluation_identity`, `report`, and the MLX loader adds `finalize`. It is not yet a drop-in replacement for either entire web runtime. A thin facade around it must supply:

| Attribute/callback | Required behavior and consumer |
| --- | --- |
| `policy_environment` | `training.peano_policy.contract.environment_record(core.environment)`, describing the **execution** authority `hydra-authority-no-imports-v1` (`ac5efc…`, no theorems), never the prompt's full247 conditioning. Required by `PolicyHead` protocol/admission (`training/peano_hydra/policy.py:288`, `:368`). |
| `evaluation_identity` | Stable JSON snapshot before constructing `PolicyHead`; include exact checkpoint/export/tokenizer/source pins, compact-v3 conditioning, restricted execution, greedy1 and local quantization. Do not mutate it with live counters/`used` flags: the portfolio rechecks identity before/after every proposal (`policy.py:681`, `:720`). |
| `identity` | Separate UI/runtime identity with `name`, `used`, `load_attempted`, selected provider ID and actual artifact/decoder fields. Hybrid result consumes this at `hybrid_runtime.py:290`. |
| `propose(goals_before, max_candidates=...)` | Pass the complete native goal tuple unchanged; at most one actual candidate. Track advice requests separately, set `initial_goals` once and `last_goals` on each request. Never pad to four. |
| `calls` | Delegate actual model-call count to the core, not the number of facade requests. New hybrid facade must not reuse old `LazyModelPolicy.calls`' completed-forward heuristic (`hybrid_runtime.py:84`), which has different failed-forward semantics. |
| `forward_passes`, `generated_token_steps` | Expose completed forwards and actual emitted greedy decisions, respectively, and include explicit `generated_token_slots`/`forward_attempts` from core. Historical beam steps are not comparable token slots. |
| `initial_goals`, `last_goals` | Needed by model-only result rendering (`model_runtime.py:636`); preserve the original full goal tuple for an unproved result. |
| `proposals`, `rejections` | Bounded presentation records derived from actual attempts: goal/prompt hash, unmodified raw decoded line when available, accepted candidate and rejection reasons. No reparsing into a fake tactic or proof. Hybrid expects these via finalization at `hybrid_runtime.py:231`; model-only currently reads attributes at `model_runtime.py:628`. Keep raw receipts in the detailed provider report, with explicit omitted-record counts if capped. |
| `emit_progress` | Use existing bounded `_progress` sink: emit preparing/loading once, proposing before inference, checking after suggestions, and verifying before final custody. Current core has no streaming token callback; do not invent intermediate token progress. |
| `finalize()` | Call core's authenticated finalizer and verify selector/caller/helper source pins. Return hybrid-compatible `model_calls`, `model_loaded`, `model_decode_attempts`, call-unit labels, forwards, token steps, proposals and authority rejections, plus full core accounting. Run in a `finally` path so failed/timed-out model work is retained. |

For the candidate hybrid facade, load on the first unresolved model request, at most once. Before loading, `calls=0`, identity/selection are metadata only, and finalization must work if heuristics prove the theorem without model use. After loading, compare supplied search capabilities to the candidate's exact execution environment. A load failure must not trigger an automatic second load or old-model fallback. One worker owns one loaded model.

## Model-only accounting requires an explicit correction

The preserved model-only search increments `model_calls` **before** asking the policy (`training/peano_policy/search.py:678`). The current old provider also increments its `calls` before prompt validation, which explains the equality at `model_runtime.py:611`. The new core intentionally spends no actual model call on an overlong prompt or pre-forward cancellation. Reusing that equality would incorrectly reject a valid bounded no-result run, or tempt implementation to fabricate inference credit.

The new runner should compare the preserved search's count with facade `advisor_requests`. In the returned public search dictionary, retain it as `model_advisor_calls` and report `model_calls`/`actual_model_calls` from the real core. Keep the original `checked.search` and portfolio records unchanged for the original runner's own validation. `model_used` must depend on actual calls, not the chosen mode.

Use head quota1 for the candidate and keep the preserved search's `candidates_per_state=4` ceiling (quota4 remains historical). This admits a real one-candidate result without padding or changing the search algorithm. Expected prompt/context/token exhaustion should return an empty tuple with a recorded bounded decline; integrity, authority-identity or loader failures must remain errors. The portfolio catches ordinary exceptions and marks degradation (`policy.py:707`), so do not suppress degraded/infrastructure results into proof claims. If a provider deadline ends the request, return/report a truthful limit/error and never reuse stale suggestions. The final native proof and independent original-theorem replay gates remain mandatory.

## Budgets, source authentication and rollout gate

The candidate keeps its tested maximum16 model calls,128 new tokens,6,144 total context and30 cumulative provider seconds. Set its call ceiling to `min(request.max_model_calls,16)`, report that effective cap, and do not silently expand it for Deep/Research profiles. Those profiles may retain their existing larger heuristic/Vampire search budget while the model adviser stops returning suggestions once its explicit budget is consumed. Pass the common outer request deadline into the core; do not reset the30-second model allowance on each suggestion. Model loading is separately bounded by the existing worker, with one initialization attempt.

Authentication must continue to use the preserved source/catalog/admission and exact quantized Base checks; the new loader already reuses them. The new live facade additionally pins/rechecks its own code, selected configuration, frozen helper sources, and all genuine candidate/export receipts. It must retain the model-only final original-source/input checks from `model_runtime.py:614`, and the native replay checks at `:621`. Do not copy the evaluation runner's broad process guard over the live worker: its existing guard allows only authenticated Vampire/adviser subprocesses needed by hybrid mode. Keep experimental model/hybrid rejection (`experimental_runtime.py:44`) unchanged.

Promotion is conditional on genuine GPU comparison and matching local candidate/baseline gates. Before switching the shared selector, exercise one unresolved case through **each** real website route, one native-heuristic closure requiring no model, and one ordinary manual replay. Verify selected model identity, actual calls, literal-candidate rejection, and original-kernel proof replay. These are specific integration gaps not covered by the current local hybrid-only runners. Rollback must select the unchanged historical provider for both routes and metadata. No results or rollout success are claimed by this design.
