## Corrections or integration requirements

1. **Input-token work on rejected forwards.** Lines 112–115 update prefill/incremental input-token counters only after logits, cache, and argmax validation succeeds. A completed numerical forward that is later rejected therefore increments `forward_passes` while reporting no corresponding input positions. Record attempted and completed input positions alongside their respective forward counters, or explicitly label these as successful-decision-only counters. This concern was sent to the backend author; it does not affect the existing policy's model-call/forward/returned-token counts.
2. **Truthful runtime identity.** `wmi_candidate_core.py:186` initializes `use_cache: false`. A future cached wrapper must explicitly report `use_cache: true`, the separately pinned backend version, fresh-per-tactic scope, and unvalidated numerical equivalence. The current shared provider backend cannot simply be replaced with a persistent cache object.
3. **Unconditional lifetime boundary.** Construct one new backend for each `CandidatePolicy.propose`, around the same already authenticated model. Close it in a `finally`/context manager that covers validation as well as execution. Input continuity/budget checks currently precede the backend's numerical `try`, so those failures rely on the host's unconditional cleanup. Never retain it in the loaded model policy across proof states, cases, or requests.
4. **Retain source and proof custody.** The wrapper must preserve original prompt functions, all ordered goals, tokenizer/checkpoint/base pins, strict EOS/UTF-8/action checks, authority postflight, and independent native replay. Add the new backend and relevant installed Qwen3/cache source pins to the separate runtime receipt/final custody check. Do not alter the current frozen comparison receipts.

## Static checks

- **RoPE and attention:** first-call caches start at zero; installed `qwen3.py:75–79` applies `cache.offset` before updating each layer. Subsequent input is exactly the previous full sequence plus its one emitted token, and all layer offsets must equal the previously consumed length. Full prefill uses causal attention; a one-token continuation attends to the complete retained prefix. No rotation, truncation, quantized cache, or cross-state reuse is proposed.
- **Head and decisions:** the backend uses the same final-normalized Qwen3 hidden state and tied embedding head as the existing full-prefix backend. WMI stays unmasked. Historical decoding uses the existing allowed IDs and sorted-index argmax, retaining lowest-ID tie handling.
- **Accounting:** unchanged callbacks charge one model call at the first actual forward attempt and one attempt/completion per decision forward. Returned EOS and invalid tokens are still charged by the existing candidate policy. Completed K/V materialization is evaluated before the completion callback. Prefill and incremental input positions are additional work measurements, not discounts to model calls.
- **Deadlines:** `forward_started` checks the existing provider/shared deadline immediately before model execution. The candidate policy checks again after charging the returned decision, so late EOS cannot become an accepted tactic. Metal evaluation itself is not cooperatively interruptible; the existing hard worker watchdog remains necessary.
- **Memory:** at 6,144 tokens the padded standard KV-cache ceiling is 1,409,286,144 bytes for float32, or half that for two-byte activations. The existing authenticated loader's 6 GiB device limit and 256 MiB allocator-cache limit remain unchanged. One serialized model/active tactic is a host requirement. `close()` drops this tactic's cache references without changing the model or global allocator; a global cache purge is unnecessary.

Before activation, bounded CPU lifecycle fixtures and serial real cached-versus-full-prefix checks remain required. Different operation shapes can change floating-point logits or greedy choices. Report any differences and use a separately versioned, fairly compared runtime; do not describe source review or estimated token-position reductions as measured acceleration.
