# Independent tokenizer-length review

This review covers the additive `cached_tokenizer_length.py` facade and its intended comparison binding. It does not activate KV caching, load a model, run inference, or change the frozen candidate core, helpers, native checker, or model files.

The installed `transformers/tokenization_utils_fast.py:287–291` implements `len(tokenizer)` by calling `backend.get_vocab_size(with_added_tokens=True)`. The saved CPU-only microcheck measured 20 such calls in 0.259889 seconds (12.994 ms/call); its complete subprocess took 0.504269 seconds. The current candidate core calls this inside the validation loop for **each prompt token** (`wmi_candidate_core.py:221`), as well as in generation checks. Caching that immutable integer removes a concrete repeated CPU cost. These measurements are not a model-inference speedup benchmark.

Source inspection found no change to encoded IDs, decoded text, vocabulary, special tokens, EOS, prompts, authority, or numerical inference:

- `encode`, `decode`, vocabulary access, and ID/token conversions call the same original tokenizer with the same arguments. There is no alternate tokenizer, truncation, repair, or new token.
- The original added vocabulary and special-token attributes are preserved. Public attributes are copied when exposed, and the backend view exposes only serialization and decoder-state inspection. Assignment/deletion and mutating tokenizer/backend APIs are not exposed.
- The exact backend JSON, full length, added vocabulary, special IDs/map, EOS/PAD/BOS are captured and compared by an explicitly uncached `verify_unchanged()` call. The wrapper is a controlled read-only facade, not a security boundary against arbitrary Python access; the authenticated underlying tokenizer must remain unmodified and unshared with external mutators.
- The original authority constraint only requires the covered read operations. Its bounded `lru_cache` uses the tokenizer object's hash: this facade remains hashable. One wrapper must be shared across fresh cases of the one loaded model so authority vocabulary memoization remains effective.
- The wrapper reports a separate tokenizer-length policy and counts cached reads. It must not replace the model selection/checkpoint/tokenizer provenance or claim a new trained model. Model calls, generated decisions, forwards, full-prefix `cache=None` inference, greedy behavior, and case limits remain unchanged.

The host must wrap **after** authenticated `prepare()`, assign only `shared.policy.tokenizer`, verify unchanged backend identity, and run tokenizer custody before/after every case and during mandatory arm-final custody. The new wrapper and harness belong to a separately pinned comparison version; both adapters must rerun the same panel, without merging the incomplete preceding arm into its scores.

The completed wrapper is 5,622 bytes, SHA-256 `98ff0d972f053a242066cc9ab26ec9103c70f7c761c605a1aee97c6657cac1e5`. Its review manifest is 3,425 bytes, SHA-256 `800e6a792d08e19360769ca60e366495f0f082060441521a13e4b3cb6177dc46`.

I inspected its source, stdout, completion manifest, and both actual tokenizer results: full/added vocabularies, frozen tokenizer identity, four saved prompt encodings/decodings, strict generation checks, and four actual authority masks agreed. Mutating public methods/attributes were blocked; mutation through a retained original reference made custody fail. Files remained unchanged and the receipt reports no model/framework load. The two loaded tokenizer views both reported full length 151,669; this is their actual post-load value, not the raw JSON backend microcheck's 151,665. The wrapper captures each original's actual length rather than hard-coding either number.

An independent file-only custody check (`6ab66a`, exit 0) verified all seven manifest file pins and the successful two-tokenizer CPU report. It imported no model framework and ran no inference.

The v3 harness draft's binding was also inspected: after `prepare()` it assigns only `shared.policy.tokenizer`, checks exact backend object identity, shares the same wrapper with fresh cases, verifies custody before/after cases and at finalization, and records boundary overhead outside the 300-second measured case but inside the existing hard watchdog. Both 18-case arms rerun under the same new contract. The draft's admission-schema adapter still needed completion when reviewed; its owner was notified to resolve that before sealing. This review is not a claim that the v3 model comparison ran or completed.
